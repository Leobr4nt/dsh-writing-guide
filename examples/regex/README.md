# 草稿与写作约定折叠规则

`draft-covenant-folding.json` 是两条可导入的显示正则，仅包含本项目编写的通用规则，不包含私人预设、角色卡、世界书、正文或凭证。

## 为什么换电脑后缺少折叠

0.5.12 起的折叠保护和0.5.13/0.5.14的滚动修复属于插件程序；将 `<draft>` / `<writing_covenant>` 转为折叠控件的正则属于预设数据，保存在用户的 `~/.dsh/writing-guide/presets/`。只克隆插件仓库不会复制用户数据。这两条规则在2026-11-13补入仓库及打包文件列表，需要导入一次到目标预设。

## 在另一台电脑启用

1. 更新仓库，或下载本目录的 `draft-covenant-folding.json`。插件运行代码使用0.5.14或以后版本。
2. 打开 **写作指导 → 预设**，找到实际写作使用的预设，点击该行 **正则 N**。也可以在 **扩展 → 正则** 中选择同一预设来源。
3. 在该预设来源下点击 **选择 JSON 文件**，选中 `draft-covenant-folding.json`，再点击 **导入到所选来源**。
4. 确认列表里有 **折叠写作约定（仅显示）** 和 **折叠草稿（仅显示）**。保持此顺序；两条都启用。若来源按钮显示“启用此来源”，点击启用；若显示“停用此来源”，说明来源已经开启。
5. 确认目标写作会话绑定的就是这份预设。回到 **写作阅读**，关闭“显示原文”，等待刷新或重新进入页面。

已有回复也会按新规则重新显示，无需重新生成。只导入配置不需要重启。界面的导入会追加规则并生成新ID；如果目标预设已有同名两条规则，就不要重复导入。已导入两次时保留一组即可。

## 换电脑后正文前的思考也展开了

思考区和上述两条草稿规则并非同一项。原机的所用预设已带针对 `<think>` / `<thinking>` 的显示规则；合成验证结果是折叠，内容仍可展开查看，并非从原始历史中删除。只安装插件不会携带该预设的规则和来源开关。

如果新电脑是在**写作阅读正文里**直接显示思考：

1. 在写作配置选中出问题的具体会话，核对它真正绑定的是哪份预设和角色卡；不要只看默认配置。
2. 在扩展页选择“正则”，跟随同一会话，切到对应“预设”来源。若按钮显示“启用此来源”，先启用；显示“停用此来源”才代表已经开启。角色卡附带规则也需各自启用来源。
3. 确认预设原有的思考显示规则存在且没有停用。用于阅读的规则必须包含“助手消息”和“写作阅读显示”；只勾“发送给模型”的规则不会影响阅读页面。不要为排查而修改原规则正文。
4. 回到写作阅读，取消“显示原文”。让页面重新读取；不需要重新生成。
5. 可以在该会话的正则预览中选“写作阅读显示效果”，分别输入 `<think>合成测试</think>正文` 和 `<thinking>合成测试</thinking>正文`。若两者仍原样返回，说明这份绑定的规则或开关尚未复原；若预览已折叠但实际回复没有折叠，需要继续按实际输出标签和渲染阶段定位，不能直接认定是开关问题。

如果新电脑另行导入了同名预设，其本地ID可能改变，旧来源开关不一定适用于新副本。若模型使用 `<analysis>`、其他标签或独立reasoning字段，这份草稿规则文件也不会自动处理；需要先核对实际格式。DSH“对话”中的独立思考面板与本页显示正则不是同一路径。

## 规则的范围

- 仅在助手消息的显示阶段生效，发送给模型的内容及原始聊天历史不变。
- 完整的 `<draft>…</draft>` 显示为默认收起的“草稿”；完整的 `<writing_covenant>…</writing_covenant>` 显示为“写作约定”。内层 covenant 没有结束标签但有外层 `</draft>` 时，使用该外层边界。
- `data-writing-fold` 标记使这些控件经过美化脚本后仍可展开。不要去掉替换文本中的标记。
- 只有这些标签包裹的内容会折叠。角色心声等其他控件依赖其所属素材原来的显示规则或脚本，不由这两条规则生成。
- 这里没有自动修改所有预设或全局规则。规则归属于你选择的预设，沿用酒馆按来源管理的逻辑。

也可以从原电脑通过预设列表“导出”，在新电脑导入更新后的完整预设，它会携带该预设的附带正则；完整预设可能包含私人内容，请使用自己的私密迁移方式。
