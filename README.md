# DSH 写作指导

为 DeepSeek Harness（DSH）增加“写作模式”。在 DSH 新建会话时选择该模式，直接在正常聊天输入框写作；插件在请求前组织预设、世界书和角色卡，回复仍由 DSH 保存到正常会话历史。

插件页面用于素材与配置管理，不要求进入插件页面进行写作。旧版作品记录保留为兼容数据。

## 版本与兼容性

- 插件版本：0.4.1，常驻浏览器运行器（实验）。
- 已验证宿主：Windows 上的 DSH 0.2.2-rc.1。
- 其他宿主版本及操作系统尚未实际验证。DSH 的插件接口变化可能需要适配。
- 模式稳定 ID 为 `writer`，显示名称为“写作模式”。
- 本仓库只包含程序、测试及说明，不含 API Key、账号凭证、个人角色卡、世界书、聊天历史或单会话绑定。

## 在另一台电脑安装

1. 安装 DSH，并在新电脑配置可用的模型连接。
2. 克隆本仓库，或下载 ZIP 并解压到固定目录。私有仓库需要先登录有权限的 GitHub 账号；若 DSH 无法认证私有 Git 仓库，使用登录后的浏览器下载 ZIP，再本地安装。
3. 在插件目录运行 `npm ci --ignore-scripts` 安装锁定的运行依赖（需要 Node.js 22+），再在 DSH“创造模式”中要求：

   > 请使用插件管理器的 install_bundle 安装这个本地插件目录：`D:\DSH-Plugins\dsh-writing-guide`。启用插件，检查“写作模式”注册成功，保留现有账号和默认模型配置。

   把示例路径换成实际解压目录，目录内应直接有 `package.json`。
4. 按安装结果提示刷新或重启 DSH。以本地目录安装时请保留该目录，不要安装后移动或删除。
5. 打开“写作指导 → 写作配置”，选择预设、世界书、角色卡和实际写作模型，保存默认配置。
6. 回到 DSH 新建会话，选择“写作模式”，发送写作要求。

首次安装仅提供基础示例预设和世界书。当前版本不会把开发机器上手工创建的默认角色卡与绑定带入新电脑；请导入自己的卡片并保存写作配置。

## 模型连接要求

当前写作请求复用 DSH 已配置的 `dsh-llm-pi-ai` provider 配置，要求：

- `api` 为 `openai-completions`；
- 有明确的 `baseURL` 和 `models` 列表；
- 使用 `apiKeyEnv` 凭证引用，并在 DSH 凭证服务或进程环境中配置对应的值；
- 所选模型必须存在于该 provider 的模型列表。

写作通道直接向配置端点的 `/chat/completions` 发送文本消息，以保留 system/user/assistant 的角色与位置。当前开发环境仅实际验证过 `catiecli / vtx-gemini-4-argon`。代码中的这一默认名称不是附送的服务或账号；新电脑必须配置可用连接，并在写作配置中重新选择。

写作会话输入框下方显示实际配置的写作模型。DSH 原有模型选择器仍代表宿主路由，可能与实际写作模型不同；诊断 `writingRoute` 为写作路由，`hostRoute` 为宿主原选择。插件不自动更改全局默认模型。

0.4.1 修复了会话配置中的输出上限和上下文上限未被采用的问题：正数会话配置覆盖全局写作设置，再受模型容量限制；会话值为 0 时沿用全局设置，仍无设置则输出默认 4096。达到输出上限时明确提示本轮未保存和重试方法，不自动重试或提交半成品状态。

请求不自动重试，整段返回而非逐字流式显示。失败、取消或非正常结束不作为成功正文。只保证发往配置端点的消息结构，无法保证第三方端点内部的转换行为。

## 功能

- Prompt Manager 预设导入、编辑、启停、排序、角色与深度注入、后置指令。
- 世界书关键词、次级关键词四种逻辑、正则、常驻、概率、有限递归、条目预算。
- Character Card JSON v1/v2 和 v3 文本字段；PNG `tEXt` 中的 `chara` / `ccv3`，优先 `ccv3`。
- 角色描述、性格、场景、示例对话、内置 `character_book`。
- 角色 system/post-history 覆盖和 `{{original}}`；未知字段在导出时尽量保留原层级。
- 默认配置及按 DSH sessionId 隔离的会话绑定；编辑仅修改草稿，点击保存才生效。
- 只接管启用的 writer 会话，不接管其他模式及辅助标题/摘要请求。

## 数据迁移

默认数据目录是当前用户的 `~/.dsh/writing-guide/`。自定义 `dataDir` 时以实际配置为准。

| 路径 | 内容 |
|---|---|
| `presets/` | 预设 |
| `worlds/` | 世界书 |
| `cards/` | 角色卡 |
| `settings.json` | 组装设置 |
| `bindings.json` | 默认配置、单会话绑定 |
| `works/` | 旧版作品数据 |

换电脑时先关闭 DSH、备份目标目录，再迁移所需素材。只迁移素材、新建聊天时，可保留 `bindings.json` 的 `defaultBinding`，把 `bindings` 设为 `{}`，再选择新电脑的模型。旧 sessionId 不能直接对应新建会话。

正常 DSH 会话历史不在本插件素材目录内；迁移历史需要宿主支持的迁移方式。不要把 `.credentials.yaml`、整个宿主 profile 或含凭证的备份提交到仓库。

## 限制

- 不是 SillyTavern 全功能复刻。未实现 CHARX、v3 资产、向量检索、完整脚本宏、定时世界书效果及多卡同时生效。
- 开场白是上下文种子，不自动出现在 UI 中作为第一条助手消息。
- token 计数是估算；上下文未知时会提示，不应当作精确 tokenizer。
- 写作模式不支持带工具调用的历史，遇到此类历史会明确拒绝。
- PNG 解析与导出回读已测试；原生文件选择框的完整自动化上传流程未完成验收。
- 当前模式没有通用代码执行或子代理工具组合。

## 社区预设与数据宏

支持按启用顺序执行 `setvar`、`getvar` 和候选列表形式的 `random`，包括赋值中的嵌套随机宏。条件块先裁剪，再展开数据宏。禁用条目不执行赋值；未知宏保留并提示。变量作用域仅限本次组装，不能替代 SillyTavern 的会话持久变量；正常写作请求使用会话和当前消息派生的种子，使同一请求预算重建时随机结果保持一致。

导入或读取预设时自动重新生成兼容性报告，写作配置页选择预设后可查看。社区预设内置正则参与发送副本处理；酒馆助手脚本可单独导入并手动运行支持的 API 子集；SPreset 扩展逻辑仍仅保留。因此提示词写作可能可用，正文美化、按钮、历史摘要过滤及脚本功能不等同于酒馆效果。采样参数不整体照搬，实际输出上限仍以写作配置和模型限制为准。

仓库中的兼容测试使用合成数据，不包含社区预设原文或用户素材。

长文本写作请求的等待上限为 180 秒；取消立即生效，无自动重试。失败诊断会记录写作通道和错误类型，超时不会被当作成功正文。

## 扩展（0.2.0 首批）

本节记录旧 QuickJS 单次运行路径；选择会话并开启常驻运行时，以文末 0.4.x 说明为准。

进入“写作指导 → 扩展”，可切换正则、提示词模板和酒馆助手。

| 功能 | 已支持 | 尚未支持 |
|---|---|---|
| 正则 | JSON导入/编辑/启停；全局→预设→卡片顺序；用户/助手发送副本、深度、捕获替换；发送与显示预览 | 正常聊天正文的显示渲染、世界书/推理块placement、SPreset绑定 |
| 提示词模板 | EJS表达式、条件、循环；getvar/setvar local/message/cache基础；预设白名单；成功后CAS保存变量；独立预览 | global/initial作用域、完整选项、世界书指令注入、模型输出模板、include、外部库 |
| 酒馆助手 | 原始脚本/数组/文件夹/含脚本预设导入；单独启停、选writer会话手动运行；chat/script变量；getChatMessages只读 | DOM、iframe界面、宿主事件、网络、定时器、slash命令、自动运行、脚本按钮、扩展全部API |

模板中的 message 变量在此版本保存为该会话最近一次模板状态，尚无按历史楼层回滚语义。普通SillyTavern宏仍为每次组装作用域，不与EJS变量完全等同。模板仅在显式启用且选中白名单预设时处理配置材料（包括其卡片和命中的世界书），真实聊天历史不执行EJS。失败/取消不提交模板变量；并发变量修改发生冲突时拒绝覆盖。

正则在可终止worker中执行。模板与脚本在QuickJS WASM独立引擎中运行，输入仅为选定会话数据与变量；不提供Node、文件、凭证、网络或DOM。单独导入脚本文件时根脚本/文件夹默认停用；随预设或角色卡整体导入时保留附带树的条目状态，但来源权限独立，且本运行器仍只手动执行。此实现是独立兼容子集，不安装原版酒馆助手/提示词模板，不承诺社区大型脚本无需修改即可运行。

扩展配置与会话变量保存在 writing-guide/extensions.json；请与个人素材一起备份，不提交仓库。正常聊天中的宿主模型选择器仍可能显示DeepSeek，实际写作模型看写作配置与诊断writingRoute。

## 来源关联管理（0.3.0）

正则与酒馆助手按 **全局 / 预设 / 角色卡** 分来源。扩展页默认跟随所选写作会话的实际绑定；与“写作配置”共用会话选择。也可切到“浏览其它素材”，检查刚导入但还未绑定的预设/角色卡，不改变会话绑定。

- 全局条目存 extensions.json；预设与角色卡条目保存在其自身 extensions 内。导入完整预设或卡片后自动识别，更新、替换或删除后重新读取，不复制成全局副本。
- 编辑、排序、启停、删除写回当前来源，影响所有共用此素材的会话。来源切换不会把编辑内容保存到另一来源；过期编辑用版本摘要拒绝覆盖。
- 正则顺序 global→preset→character。预设/角色卡须先“启用此来源”，再看条目的 disabled。全局正则无额外允许列表。
- 助手为来源开关 + 文件夹 enabled + 单条 enabled 三层判定。全局开关只控制全局脚本，不控制其它来源。新预设/角色卡来源默认不允许；原有全局开关保留。
- 整体导入素材保留内嵌 flags；单独导入正则按ST生成新UUID并保留disabled；单独导入助手脚本/文件夹重新分配ID并停用根节点，文件夹孩子保留启停状态。
- 支持角色卡 tavern_helper 键值对数组，以及旧 TavernHelper_scripts 的 value 包装/文件夹与按钮迁移；首次编辑写成 canonical tavern_helper，保留变量与未知字段。
- 导出遵守助手 export_with.data / export_with.button，导出时清理对应字段，不修改本地素材。
- 删除素材会移除其来源允许记录，重新导入相同id不会继承删除前的许可。

行为依据：SillyTavern regex engine/index（读取、保存、来源允许列表、单独导入与删除事件）；JS-Slash-Runner store/scripts、settings/preset、settings/character、type/backward、panel/script/Toolbar.vue。具体commit见 THIRD_PARTY_NOTICES.md。

明确的宿主差异：来源允许列表用稳定DSH实体id；内部用来源+实体+脚本复合身份防止同id串数据，尚未复刻酒馆切换素材时重写冲突脚本ID的生命周期。未开启常驻运行的会话仍使用旧 QuickJS 手动路径。来源管理实现不等于整个酒馆运行环境已经移植。

## 角色卡内置世界书（0.3.1）

导入JSON/PNG角色卡时，内置character_book会转换为独立世界书并出现在世界书列表，角色卡以extensions.world和本地稳定ID关联该书。随后写作从世界书列表读取当前版本；编辑书后下次写作立即使用新内容，导出卡片也使用当前关联书。

该书即使未选为全局书，仍可作为当前角色的关联书参与；同时在全局和角色关联中出现时只计一次。删除关联书后报告缺失，不静默重新使用卡内旧副本。同名书内容不同时返回冲突，需明确确认覆盖；重导入相同内容复用现有书。

PNG上限20MB，解码后的JSON上限12MB；PNG导入端点允许30MB的JSON/base64请求体。原始character_book保留在rawCharacterBook和世界书originalData中，规范化/导出保留扩展字段与未知字段，不把保存成功等同于所有MVU/模板扩展已实现。

行为参照SillyTavern world-info.js的importEmbeddedWorldInfo、convertCharacterBook、getCharacterLore，以及characters.js的convertWorldInfoToCharacterBook。自动执行导入动作是本次用户明确要求；酒馆原版会按设置提示是否导入。

## 元数据验收工具

`node scripts/verify-suite.mjs <本地 validation-suite.json 路径> <状态报告.json 路径>`

使用本地固定套装，在现有隔离运行器中检查模板与助手；不展示素材正文、脚本日志或原始错误，不发送模型请求，不改变来源开关/素材/变量。输出仅含计数、能力标记和固定错误类别。退出码0表示接受，2表示验收未通过，1表示验收基础设施错误。

逐片段执行与语法检查不等于完整业务通过；无异常返回也不等于MVU初始化成功。完整MVU模块、常驻实例、宿主事件和输出更新链路尚未实现时，工具明确记录未通过，不使用空对象或模拟成功隐藏缺口。

## 常驻运行器（0.4.0 实验功能）

完整安装依赖后，需要本机存在 Chrome 或 Edge；也可用环境变量 DSH_WRITING_BROWSER 指定浏览器可执行文件。只启动独立的无界面浏览器，不使用用户浏览器资料、Cookie或账号。新电脑首次启用时会缓存公开模块依赖，之后按SHA256校验本地缓存。

在扩展页选择一个写作会话，开启“本会话常驻运行”，同时启用所需预设/角色卡助手来源，并在提示词模板页勾选该预设。仅选中的会话使用新运行器；其它会话保持原有路径。浏览器保持脚本实例、模块和事件监听，生成前运行模板，回复后触发消息事件和MVU更新，成功后按版本保存状态。失败/取消丢弃本轮浏览器事务。最多保留4个会话，空闲5分钟释放浏览器并在需要时恢复。

运行环境不获得DSH模型凭证；脚本网络请求均拦截。仅模块构建器可获取白名单公开模块与其npm依赖，并记录哈希。不要把运行器状态、素材和模块缓存提交到GitHub。

已验证核心MVU初始化、消息事件变量更新与当前组装模板展开；附带脚本的部分界面API仍报错，不代表全部酒馆助手功能完成。世界书运行改动目前保存在会话副本，不自动回写原始素材；独立浏览器界面尚未映射到DSH聊天正文。

使用 `node scripts/verify-resident-suite.mjs <本地validation-suite.json> <状态报告.json>` 可进行只输出状态/计数的隔离验收；不展示正文或变量值，不调用模型。旧的 verify-suite.mjs 验证的是旧QuickJS运行器，两者结果不能混用。

跨电脑继续开发请先阅读 [HANDOFF.md](HANDOFF.md)，包含固定套装、不可展示素材内容的限制、安装与迁移步骤及最后验收停止点。

## 0.4.1 本机验证与界面接入

- 在 DSH 0.2.2-rc.1 的正常 Agent/Session 执行链中，用已配置的 `catecli / vtx-gemini-4-argon` 完成首轮生成；关闭验收进程后恢复同一会话，第二轮也完成。两轮均保存助手消息和常驻状态，变量版本由 1 递增至 2；没有向开发聊天输出正文。
- 输入框下方使用正式 `conversation.composer.dock` 扩展位置显示写作模型、常驻状态和脚本按钮。按钮只派发给当前启用来源的脚本；变量冲突或处理失败不提交状态。需要改写既有聊天正文的按钮会拒绝执行，尚未提供宿主历史编辑。
- 补齐 `SillyTavern.loadWorldInfo`、UUID、脚本名称/说明和按钮更新接口，安装固定版本的 jQuery UI；修复世界书位置、次级关键词逻辑、递归和时效字段读写丢失。
- 外部变量修改或素材更新会使旧常驻实例失效，重新载入最新状态；避免覆盖手动更新的变量。会话状态支持进程重建恢复，仍不等于跨会话全局共享语义。
- 固定套装仍报告 1 条被拦截的网络请求和 1 条未识别的脚本引用错误。核心 MVU/模板验收通过，不宣称完整酒馆兼容。任意脚本自建 DOM、图鉴与状态栏尚未映射到可见 DSH 页面；正文显示正则和世界书自动写回也仍待开发。
- 常驻验收工具分别报告 `corePassed`、`fullCompatibility` 和 `inputsAndStateUnchanged`；基础设施失败退出码为 1，核心失败为 2。依赖缓存允许新增，输入素材和持久业务状态需保持不变。
