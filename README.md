# DSH 写作指导

为 DeepSeek Harness 增加“写作模式”。在正常聊天输入框创作，插件负责预设、世界书、角色卡、正则和扩展处理，回复保存在 DSH 会话历史中。

当前版本 **0.5.15**。已验证 Windows / DSH **0.2.2-rc.1**。这不是完整 SillyTavern 的移植；支持范围和仍未解决的问题见 [KNOWN_ISSUES.md](KNOWN_ISSUES.md)，开发记录见 [HANDOFF.md](HANDOFF.md)。

## 安装与更新

1. 克隆本仓库到固定目录；私有仓库需先登录有权限的 GitHub 账号。
2. 使用 Node.js 24.9+ 运行 `npm ci --ignore-scripts`。
3. 在 DSH 插件管理器安装本地目录并启用。目录内应直接包含 `package.json`。
4. 正常退出并重启 DSH。以本地目录安装后，请不要移动或删除目录。

桌面版内置命令也支持安装，例如：

```powershell
& '<DSH安装目录>\resources\runtime\cli\bin\dsh.cmd' plugin --profile desktop add '<本地插件目录>'
```

升级插件前备份自己的 `~/.dsh/writing-guide/` 数据。更新代码与依赖后正常重启，不要反复 remove/install 热重载正在运行的脚本。

## 开始写作

1. 在 DSH 模型设置中配置可用连接。
2. 打开“写作指导 → 写作配置”，选择预设、角色卡、世界书和写作模型，点击保存。世界书支持搜索和多选；角色卡关联书自动加入并去重。
3. 新建 DSH 会话，选择“写作模式”，直接输入写作要求。
4. 想看显示正则、美化及隐藏结果时，切到同一会话的 **写作阅读**。原聊天输入框继续可用；**对话**保留原始记录。
5. 脚本套装在“扩展”中启用对应预设/角色卡来源、模板白名单和常驻运行。可启用默认常驻运行，再按会话单独关闭。

素材库页负责管理，正常创作在会话内完成。新安装只有示例素材，不附送私人卡片、模型服务、账号或 API Key。

在“写作配置 → 写作素材 → 用户角色名字”填写你在故事中代表的角色名，相当于酒馆 Persona 名字。`<user>` / `{{user}}` 会在组装时替换为它；`<char>` / `<bot>` / `{{char}}` 使用角色卡名字（大小写不敏感）。默认配置和会话独立配置各自保存；留空或旧配置缺字段时回退“用户”。保存影响后续请求，不改写已有正文。角色名与第一/第二/第三人称要求是不同设置，第三人称选项仍由预设决定。

原“注入”页已撤下。扫描深度、世界书预算、全局输出/上下文等仍生效的参数位于“写作配置 → 全局高级设置”，单独保存并作用于所有写作会话。角色卡字段优先，全局字段仅补充缺省值。素材库不再显示旧模式标签或根据旧预设设置标记“注入中”。

在“配置应用于”选择具体会话，可查看本次 DSH 启动以来该会话最近一次请求的模型、阶段与消息角色计数。默认配置不冒充某个会话的请求记录；诊断不返回素材、正文、脚本报错原文或变量。旧版作品页只提供查看和导出，模型工具不再提供独立作品生成。旧 HTTP 作品写入/生成及系统段预览接口仅作为历史兼容接口保留，新页面不使用它们。

写作模式不再经过旧系统段注入。停用写作接管后回到宿主通道，不会自动带入旧注入页选择的预设。端点、模型或凭证校验失败时，诊断显示尚未发送；只有进入 HTTP 请求时才标记请求模型。

## 模型与生成

当前写作通道使用 DSH `dsh-llm-pi-ai` 配置，要求 `api=openai-completions`、明确的 `baseURL` / `models` 和 `apiKeyEnv` 凭证引用。所选模型必须在连接列表中。

输入框上方显示实际写作模型。宿主原生模型选择器代表宿主路由，可能不同；诊断中的 `writingRoute` 是实际写作路由。插件不修改全局默认模型。

每个会话可覆盖输出上限、上下文窗口和作者注。输出上限为 0 时沿用全局写作设置，再无设置时默认 4096；最终仍受模型容量限制。预算与发送的输出上限一致。

“写作配置 → 高级参数 → 请求超时（秒）”默认 **600 秒（10 分钟）**，可设 1–3600 秒。可保存为默认配置，或在上方选择会话后单独设置；已设独立配置的会话保持自己的值。旧配置缺少该字段时使用 600 秒，无需重新导入素材。修改从下一次请求生效，最近请求状态显示该次实际超时值。

超时从每次 HTTP 请求发出计时，直到完整响应读取完成，包含模型思考和生成时间；SPreset 工具往返的每次模型请求分别计时。不自动重试，可随时取消；超时、截断、失败和取消均不作为成功正文或变量状态提交。此设置不能延长上游模型服务自身的超时限制。

## 素材与普通宏

- 预设支持 Prompt Manager 条目顺序、启停、role、深度与后置指令。
- 世界书支持关键词、次级关键词逻辑、正则、常驻、概率、有限递归和预算。
- 角色卡支持 JSON v1/v2/v3 文本字段，以及 PNG `tEXt` 中的 `chara` / `ccv3`。内置书导入为独立可编辑世界书，导出使用当前关联书。
- 正常写作会话中，`setvar/getvar/addvar/incvar/decvar/hasvar/deletevar` 及 `varexists/flushvar` 共用持久聊天变量。与助手 chat、EJS local 使用同一张会话表，跨轮和重启可恢复。
- 预算重建使用同一事务快照，失败/取消/并发冲突不提交，预览不写回。明确的 `setvar` 仍每次覆盖，含 `random` 的赋值下一轮仍重新抽取；不会自动把初始化代码变成只执行一次。
- 消息级 MVU 变量、聊天变量和全局变量是不同作用域；不宣称所有同名变量自动互通。

## 正则与写作阅读

正则按全局 → 当前预设 → 当前角色卡执行，来源、条目开关分别生效。发送与显示是不同路径：`promptOnly` 处理发送副本，`markdownOnly` 在“写作阅读”显示；不改原始历史。

写作阅读支持 Markdown、HTML/CSS、`details` 折叠以及空白替换隐藏。可随时打开“显示原文”。普通静态正文使用无脚本 iframe；完整 HTML 美化文档在独立浏览器中执行，其渲染后的 HTML 以可选择文本的隔离 iframe 显示，控件事件传回独立运行器，不能接触 DSH 页面或凭证。当前在回复完成后刷新，不是逐 token 渲染。

0.5.1 修复完整 HTML 被当作 Markdown、ID/控件被移除、混合 HTML/Markdown 中脚本被改坏和远程插图丢失的问题。公开 HTTPS 图片通过不带 Cookie/凭证的本地下载器获取，逐跳校验地址并缓存为内联图片。脚本本身的网络、WebSocket、导航、文件和弹窗仍被限制。字体/部分外部资源不加载，使用本地回退。正文可直接选择和复制，按钮与输入框在文档中直接操作；显示设置按会话和消息隔离保存。

0.5.2 修复透明文档截图的浅字白底：仅在文档没有设置背景时，根据文字颜色补足底色，并在操作后重新检查。脚本界面增加深色宿主样式、设置折叠和控件间距；仅执行后台脚本的空 iframe 不占位置，稍后生成的可视内容会重新显示。兼容提示按错误类别和公开接口归类，并保留累计次数；重复报错仍会使失败的按钮操作回滚，不表示对应功能已经修好。

扩展页提供正则名称、表达式、替换内容、位置和用途表单，高级 JSON 可展开编辑。世界书、预设、角色卡和旧版作品提供名称搜索。

酒馆助手的“编辑”和“新建”会显示名称、脚本代码、作者备注并自动定位；文件夹编辑显示名称。修改后保存回所属来源，取消不落盘；变量、按钮、导出选项和未知字段保留，可在高级 JSON 中修改。点击编辑不会自动启用或执行脚本。

显示规则生成的草稿／写作约定折叠（`details[data-writing-fold="draft"]` 或 `writing_covenant`）会在最终阅读界面保持为可点击的原生折叠区，避免正文美化脚本将标签剥成普通文字。开合状态在当前阅读视图的刷新和尺寸变化后保留；更换消息或内容版本后重置。若美化脚本丢弃了占位位置，折叠内容在文末保留。这些折叠内部作为静态阅读内容处理，不执行其中脚本或转发其自定义控件事件；折叠外的原有控件继续使用隔离运行器。

**换电脑后缺少草稿折叠：**折叠显示程序随插件安装，但折叠正则属于预设数据，不会随 `git clone` 自动启用。仓库现附 [两条纯规则 JSON](examples/regex/draft-covenant-folding.json) 和 [导入步骤](examples/regex/README.md)。在实际使用的预设行点击“正则 N”，选择该文件并“导入到所选来源”，确认来源及条目启用，再进入写作阅读。已有同名规则时不要重复导入。单独导入不需要重启，也不需要重新生成正文。

正文前的思考也直接展开时，另检查所用预设原有的 `<think>` / `<thinking>` 显示规则、预设／角色卡来源开关、当前会话绑定和“显示原文”选项。Git不迁移这些本地开关；新导入的同名素材也可能是另一个本地ID。完整步骤见上述导入说明，不要把草稿两条规则当成所有思考标签的通用处理器。

0.5.13 修复折叠、设置控件、输入及刷新时的阅读跳位：iframe 测量高度期间同步保留外层滚动位置，避免临时缩小高度造成回顶或跳到底部。操作期间主动滚动会保留最新位置；若收起内容后页面已不足原滚动高度，浏览器仍会正常限制到新页面范围。

0.5.14 补上美化正文的延迟布局及重载中间阶段：阅读投影不使用 `content-visibility:auto` 的占位高度，旧页面的高度监听也不会测量尚未加载完整的新页面。源脚本页面继续保留原样式；这避免连续操作下方心声按钮时跳到上方位置。

0.5.15 为写作阅读增加会话独立的位置记忆：再次打开时恢复上次离开的滚动位置，没有记录时才定位到最新内容。恢复会等待异步正文和多段美化页面完成排版；加载过程中主动滚动或操作控件会停止自动定位。后台刷新和生成状态变化不重新触发定位。位置仅保存在当前电脑的 DSH 前端存储中（会话 ID 和滚动坐标），不含正文、不上传 GitHub，也不跨电脑同步。更新后从首次阅读开始记录；若正文、折叠状态或窗口布局改变，坐标可能对应不同段落，超出新页面长度时定位到可用范围。

## 酒馆助手与模板

常驻运行器使用本机 Chrome/Edge 的独立无界面实例，不读取用户浏览器资料或 Cookie。可用 `DSH_WRITING_BROWSER` 指定可执行文件。

已支持模块加载、部分事件、MVU、聊天/脚本变量、世界书接口、按钮和异步 EJS。成功生成后提交状态，失败/取消丢弃本轮事务；变量或素材外部更新会使旧实例失效。

0.5.8 补齐非驻留模板执行的 `getMessageVar/getLocalVar/getGlobalVar` 及 Lodash，避免关闭常驻运行时出现函数未定义。两条模板路径共用读取接口：未指定消息筛选时 `getMessageVar` 读取合并缓存（global → local → message，顶层覆盖），支持默认值、路径、整表、clone、JSON 字符串 index 和 noCache。`setLocalVar/setMessageVar` 复用现有事务写入。全局读取目前来自该会话保存的 global 快照，尚不是酒馆跨聊天全局共享；`withMsg`、initial 和多 swipe 查询仍明确不支持。

会话输入框上方可操作脚本按钮。**写作阅读 → 脚本界面**可查看独立浏览器画面，点击、输入、发送常用键和滚动；图鉴、状态栏等是否可运行仍取决于脚本所需 API。需要修改原聊天历史的操作会明确拒绝。

最多保留 4 个常驻会话，空闲 5 分钟释放。脚本网络被阻断；只有模块构建器可下载白名单公开依赖并校验缓存哈希。完整生命周期与尚不支持的接口见问题清单。

## SPreset

按公开源码独立实现，保留未知字段。支持以下执行路径：

| 功能 | 当前实现 |
|---|---|
| RegexBinding | 绑定正则优先，补入不同 id 的原生规则；编辑时同步，避免重复执行 |
| ChatSquash | 前后缀、条件标签、历史区分组、分隔符、合并后函数与按前缀重新拆分 |
| MacroNest | 受支持数据宏的有界嵌套 |
| MessageInjections | OpenAI 兼容工具调用与返回示例历史 |
| ToolBindings | 启用条目的纯函数工具、参数校验、隔离执行和有限模型往返 |
| OutputPreprocessing | 整段输出函数，支持字符串或 output/hold 返回 |
| FinalRequestProcessing | 处理请求副本，保持原模型、凭证边界和输出上限 |
| FixedPresetName | 导入使用固定名称，保留本地 id |
| ForcedPostProcessing | 文本 merge/semi/strict/single 及保留工具变体 |

预设编辑页提供常用 SPreset 控件；完整配置可随预设 JSON 导入。处理函数运行于 QuickJS 隔离解释器，只有传入的 JSON 数据，不获得 DSH 凭证、网络、文件或 DOM。更多模式差异及明确拒绝的选项见 [问题清单](KNOWN_ISSUES.md#d-spreset)。

## 数据与迁移

默认数据根：`~/.dsh/writing-guide/`；自定义 `dataDir` 时以配置为准。

| 路径 | 内容 |
|---|---|
| `presets/`、`worlds/`、`cards/` | 预设、世界书、角色卡 |
| `settings.json`、`bindings.json` | 全局组装设置、默认及单会话绑定 |
| `extensions.json` | 扩展开关、普通宏/脚本/模板变量、常驻状态 |
| `runtime-modules/` | 白名单模块与完整性清单 |
| `reading-images/`、`reading-styles/`、`reading-settings/` | 公开插图及样式缓存、逐消息美化偏好 |
| `works/` | 旧版作品数据 |

迁移前正常退出 DSH 并备份目标目录。新机器需要重新配置模型，旧 Session ID 不能直接对应新会话。DSH 正常聊天历史由宿主保存，独立于本插件素材库。

不要提交私人素材、缓存中的第三方脚本、聊天正文、API Key、`.credentials.yaml` 或整个宿主 profile。

## 0.5.3 正文文本修复

修复“完整美化”将整段正文截图成PNG的问题。正文现在显示渲染后的真实HTML文本，支持文字选择/复制、原生表单控件、details展开及按内容高度排版；不再限制为前10000像素。图片仍是原有插图，局部canvas可转换为图片，但不把整篇文字栅格化。

参考SillyTavern script.js 的 messageFormatting/mes_text，以及JS-Slash-Runner的panel/render/Iframe.vue、iframe.ts：正文应为DOM，前端界面应在iframe中呈现。DSH仍在独立浏览器执行源脚本，再向阅读iframe提供净化后的DOM并代理控件事件；不等同于酒馆完整同源脚本环境。动态动画、拖拽及宿主API兼容仍属未完成项。

新增reading-dom和reading-client测试，验证实际React组件的文本选择、输入、折叠、长文末尾、窄屏与脚本隔离。固定套装仅程序结构检查：243个文本节点、39个控件、5张插图，正文非整页图片；未显示素材内容、未调用模型、未改原始历史。

## 0.5.4 混合文档与样式表修复

完整HTML前端文档在Markdown解析前分离为独立片段，普通正文和每个前端文档分别显示，避免把HTML围栏/资源标签当作文字、跨文档CSS污染。公开HTTPS样式表经过与图片相同的地址/DNS/重定向校验后本地缓存内联；不携带凭证，每份限制2MB。二级@import/字体等请求仍受限制，失败样式有提示。动态CSSOM规则和根主题属性也随DOM保留。

截图对应历史消息结构复测：3个显示片段，外部样式2份恢复，22个控件默认只显示6个，代码围栏和转义资源标签均为0，投影前后控件样式差异0。素材正文/脚本不展示，原始会话不修改。另一固定套装的结构回归仍有1个按钮颜色差异，未据此宣称全部样式完全一致。

## 0.5.5 摘要折叠边界修复

前端代码围栏和完整HTML文档之间含注释或空行时，仍将它们视为一个前端块并成对移除围栏，保留HTML注释。避免遗留结束围栏被Markdown解释成新的代码块，导致后续details/summary显示为标签文本。摘要继续按浏览器原生details折叠，原始消息和摘要内容不修改；不对有意展示的代码示例做全局反转义。

## 0.5.6 素材附带扩展入口

角色卡和预设列表直接显示“正则 N / 脚本 N”，点击进入对应素材的扩展来源与类型，无需先改默认配置。脚本数量包含目录内节点；预设正则使用与执行路径一致的SPreset绑定合并规则。列表入口使用只读浏览选择，不修改会话绑定和来源启停；点击顶部“扩展”仍回到当前写作配置。
